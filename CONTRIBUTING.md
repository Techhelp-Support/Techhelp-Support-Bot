# 🤝 Mitwirken am TechHelp Support Bot

Vielen Dank für dein Interesse, den **TechHelp Support Bot** mitzugestalten! 💙

Der TechHelp Support Bot entwickelt sich gemeinsam mit seiner Community weiter. Du kannst uns dabei helfen, neue Ideen zu sammeln, bestehende Funktionen zu verbessern, Fehler zu melden oder bei der Entwicklung mitzuwirken.

---

## 💡 Möglichkeiten zur Mitarbeit

Du kannst auf verschiedene Arten zum Projekt beitragen:

* 💡 Neue Funktionen vorschlagen
* 🛠️ Bestehende Funktionen verbessern
* 🐛 Fehler melden
* 🎨 Verbesserungen an der Benutzeroberfläche vorschlagen
* 📚 Dokumentation verbessern
* 💻 Code beitragen
* 🔍 Bestehende Issues testen
* 💬 Bei Diskussionen zu neuen Funktionen helfen

Auch kleine Beiträge können einen Unterschied machen.

---

## 💡 Neue Ideen

Du hast eine Idee für eine komplett neue Funktion?

Dann erstelle bitte ein Issue mit dem Template:

**💡 Neue Idee**

Beschreibe dabei möglichst genau:

* Was möchtest du hinzufügen?
* Welches Problem soll gelöst werden?
* Wie könnte die Funktion funktionieren?
* Für welchen Bereich des Bots ist sie gedacht?
* Gibt es Beispiele für die Verwendung?

Je genauer deine Beschreibung ist, desto einfacher können wir deine Idee verstehen.

---

## 🛠️ Verbesserungen

Wenn eine bereits vorhandene Funktion verbessert werden könnte, verwende bitte:

**🛠️ Verbesserung**

Beschreibe dabei:

* Wie funktioniert die Funktion aktuell?
* Was könnte verbessert werden?
* Wie stellst du dir die Verbesserung vor?
* Welchen Vorteil hätte die Änderung?

---

## 🐛 Fehler melden

Wenn du einen Fehler gefunden hast, beschreibe ihn möglichst genau.

Eine gute Fehlermeldung sollte enthalten:

### 🔴 Problem

Was funktioniert nicht?

### 🔁 Schritte zur Reproduktion

Wie kann der Fehler ausgelöst werden?

Beispiel:

```text
1. Dashboard öffnen
2. Server auswählen
3. Ticket-Konfiguration öffnen
4. Einstellung speichern
5. Fehler tritt auf
```

### ✅ Erwartetes Verhalten

Was sollte eigentlich passieren?

### ❌ Tatsächliches Verhalten

Was passiert stattdessen?

### 📎 Weitere Informationen

Screenshots, Fehlermeldungen, Logs oder andere hilfreiche Informationen können ebenfalls hinzugefügt werden.

---

## 💻 Code beitragen

Wenn du selbst Code zum Projekt beitragen möchtest, achte bitte auf eine saubere und nachvollziehbare Umsetzung.

### Vor dem Pull Request

Bitte überprüfe:

* [ ] Der Code funktioniert wie erwartet.
* [ ] Bestehende Funktionen wurden nicht unnötig beschädigt.
* [ ] Neue Funktionen wurden getestet.
* [ ] Offensichtliche Fehler wurden behoben.
* [ ] Keine Zugangsdaten oder Tokens wurden veröffentlicht.
* [ ] Der Code ist verständlich und nachvollziehbar.
* [ ] Notwendige Dokumentation wurde angepasst.

---

## 🔀 Pull Requests

Wenn du Änderungen am Code vorgenommen hast, kannst du einen Pull Request erstellen.

Beschreibe darin kurz:

### Was wurde geändert?

Beispielsweise:

> Das Ticket-System wurde um eine automatische Schließfunktion erweitert.

### Warum wurde es geändert?

Beispielsweise:

> Tickets sollen nach einer konfigurierbaren Zeit ohne Aktivität automatisch geschlossen werden können.

### Was wurde getestet?

Beispielsweise:

> Die Funktion wurde mit verschiedenen Zeitintervallen getestet.

---

## 🏷️ Commit-Nachrichten

Wir empfehlen verständliche Commit-Nachrichten.

### Beispiele

```text
feat: automatische Ticketschließung hinzugefügt
fix: Ticket-Übernahme repariert
fix: Dashboard-Fehler behoben
docs: README aktualisiert
style: Dashboard-Layout verbessert
refactor: Ticket-System überarbeitet
```

Vermeide möglichst unklare Nachrichten wie:

```text
update
test
änderung
fix
stuff
```

---

## 🔐 Sicherheit

Bitte veröffentliche **keine vertraulichen Informationen** in Issues, Pull Requests oder im Repository.

Dazu gehören insbesondere:

* Discord Bot Tokens
* API-Keys
* Passwörter
* Datenbank-Zugangsdaten
* Webhook-URLs mit geheimen Informationen
* OAuth-Secrets
* Private Schlüssel
* Andere Zugangsdaten

### 🚨 Sicherheitslücken

Eine Sicherheitslücke sollte **nicht öffentlich als normales Issue veröffentlicht werden**.

Melde sicherheitsrelevante Probleme stattdessen direkt an das zuständige TechHelp-Team.

---

## 📋 Issues

Bitte überprüfe vor dem Erstellen eines neuen Issues, ob bereits ein ähnliches Issue existiert.

Dadurch vermeiden wir doppelte Vorschläge und können bestehende Diskussionen an einem Ort führen.

Verwende nach Möglichkeit das passende Issue-Template:

* 💡 **Neue Idee** → neue Funktion oder Möglichkeit
* 🛠️ **Verbesserung** → Verbesserung einer bestehenden Funktion

---

## 💬 Diskussionen

Nicht jede Idee muss sofort vollständig ausgearbeitet sein.

Wenn du dir bei einer Umsetzung unsicher bist, kannst du deine Idee trotzdem einreichen. Das TechHelp-Team und andere Community-Mitglieder können anschließend gemeinsam darüber diskutieren.

Respektiere dabei andere Meinungen und bleibe sachlich.

---

## 🚦 Bearbeitung von Vorschlägen

Eingereichte Vorschläge können unterschiedliche Zustände durchlaufen:

```text
💡 Idee
   ↓
🔍 Prüfung
   ↓
💬 Diskussion
   ↓
📋 Planung
   ↓
🛠️ Entwicklung
   ↓
✅ Umsetzung
```

Nicht jeder Vorschlag wird automatisch umgesetzt.

Ein Vorschlag kann beispielsweise zusammen mit einem bestehenden Vorschlag bearbeitet, zurückgestellt oder abgelehnt werden.

---

## 📜 Verhaltensregeln

Bei der Mitarbeit am Projekt erwarten wir einen respektvollen Umgang miteinander.

Bitte:

* 🤝 respektiere andere Personen
* 💬 bleibe sachlich
* 🚫 keine Beleidigungen oder persönlichen Angriffe
* 🚫 kein Spam
* 🚫 keine absichtlichen Störungen des Projekts
* 🔐 veröffentliche keine vertraulichen Daten
* 💡 konzentriere dich auf das Projekt und seine Weiterentwicklung
