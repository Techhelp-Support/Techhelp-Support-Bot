## 🇩🇪 Deutsch

Vielen Dank für dein Interesse, den **TechHelp Support Bot** mitzugestalten! 💙

Der TechHelp Support Bot entwickelt sich gemeinsam mit seiner Community weiter. Du kannst helfen, neue Ideen zu sammeln, Funktionen zu verbessern, Fehler zu melden oder bei der Entwicklung mitzuwirken.

### 💡 Möglichkeiten zur Mitarbeit

- 💡 Neue Funktionen vorschlagen
- 🛠️ Bestehende Funktionen verbessern
- 🐛 Fehler melden
- 🎨 Verbesserungen an der Benutzeroberfläche vorschlagen
- 📚 Dokumentation verbessern
- 💻 Code beitragen
- 🔍 Bestehende Issues testen
- 💬 Bei Diskussionen zu neuen Funktionen helfen

Auch kleine Beiträge machen einen Unterschied.

### 💡 Neue Ideen

Für eine komplett neue Funktion erstelle bitte ein Issue mit dem Template **💡 Neue Idee** und beschreibe: Was möchtest du hinzufügen? Welches Problem soll gelöst werden? Wie könnte die Funktion funktionieren? Für welchen Bereich ist sie gedacht?

### 🛠️ Verbesserungen

Für eine bereits vorhandene Funktion nutze das Template **🛠️ Verbesserung** und beschreibe: Wie funktioniert es aktuell? Was könnte verbessert werden? Wie stellst du dir die Verbesserung vor? Welchen Vorteil hätte die Änderung?

### 🐛 Fehler melden

Eine gute Fehlermeldung enthält: das **Problem**, **Schritte zur Reproduktion**, das **erwartete Verhalten**, das **tatsächliche Verhalten** sowie ggf. Screenshots, Logs oder Fehlermeldungen.

### 💻 Code beitragen – Checkliste vor dem Pull Request

- [ ] Der Code funktioniert wie erwartet.
- [ ] Bestehende Funktionen wurden nicht unnötig beschädigt.
- [ ] Neue Funktionen wurden getestet.
- [ ] Keine Zugangsdaten oder Tokens wurden veröffentlicht.
- [ ] Der Code ist verständlich und nachvollziehbar.
- [ ] Notwendige Dokumentation wurde angepasst.

### 🏷️ Commit-Nachrichten

Verständliche Nachrichten helfen allen. Beispiele:

```text
feat: automatische Ticketschließung hinzugefügt
fix: Ticket-Übernahme repariert
docs: README aktualisiert
style: Dashboard-Layout verbessert
refactor: Ticket-System überarbeitet
```

Vermeide unklare Nachrichten wie `update`, `fix`, `stuff`.

### 🔐 Sicherheit

Veröffentliche **keine vertraulichen Informationen** (Bot-Tokens, API-Keys, Passwörter, Datenbank-Zugangsdaten, Webhook-URLs, OAuth-Secrets, private Schlüssel). Sicherheitslücken bitte **nicht** öffentlich als Issue melden – siehe [SECURITY.md](./SECURITY.md).

### 📜 Verhaltensregeln

Wir erwarten einen respektvollen Umgang. Bleib sachlich, keine Beleidigungen, kein Spam, keine absichtlichen Störungen. Es gilt der [Verhaltenskodex](./CODE_OF_CONDUCT.md).

## 🇬🇧 English

Thank you for your interest in helping shape the **TechHelp Support Bot**! 💙

The TechHelp Support Bot evolves together with its community. You can help gather new ideas, improve features, report bugs, or contribute to development.

### 💡 Ways to contribute

- 💡 Suggest new features
- 🛠️ Improve existing features
- 🐛 Report bugs
- 🎨 Suggest UI improvements
- 📚 Improve documentation
- 💻 Contribute code
- 🔍 Test existing issues
- 💬 Help with discussions about new features

Small contributions matter too.

### 💡 New ideas

For a brand-new feature, open an issue using the **💡 New idea** template and describe: What do you want to add? What problem does it solve? How could it work? Which area is it for?

### 🛠️ Improvements

For an existing feature, use the **🛠️ Improvement** template and describe: How does it currently work? What could be improved? How do you imagine the improvement? What's the benefit?

### 🐛 Reporting bugs

A good bug report includes: the **problem**, **steps to reproduce**, the **expected behavior**, the **actual behavior**, and optionally screenshots, logs, or error messages.

### 💻 Contributing code – checklist before the pull request

- [ ] The code works as expected.
- [ ] Existing functionality wasn't unnecessarily broken.
- [ ] New functionality was tested.
- [ ] No credentials or tokens were exposed.
- [ ] The code is clear and understandable.
- [ ] Necessary documentation was updated.

### 🏷️ Commit messages

Clear messages help everyone. Examples:

```text
feat: add automatic ticket closing
fix: repair ticket claiming
docs: update README
style: improve dashboard layout
refactor: rework ticket system
```

Avoid vague messages like `update`, `fix`, `stuff`.

### 🔐 Security

Do **not** publish confidential information (bot tokens, API keys, passwords, database credentials, webhook URLs, OAuth secrets, private keys). Please do **not** report vulnerabilities as public issues – see [SECURITY.md](./SECURITY.md).

### 📜 Code of conduct

We expect respectful interaction. Stay constructive, no insults, no spam, no intentional disruption. The [Code of Conduct](./CODE_OF_CONDUCT.md) applies.
