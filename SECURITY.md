## 🇩🇪 Deutsch

### Unterstützte Versionen

| Version | Unterstützt |
| ------- | ----------- |

### Eine Sicherheitslücke melden

Wir nehmen Sicherheit ernst. Wenn du eine Sicherheitslücke findest, öffne **kein** öffentliches Issue und diskutiere sie **nicht** öffentlich.

Melde sie stattdessen privat, zum Beispiel:

- Über ein privates GitHub Security Advisory (bevorzugt, falls aktiviert)
- Direkt an die Maintainer über GitHub
- Über den privaten Meldeweg des Repositories, falls vorhanden

Bitte gib an: Beschreibung der Lücke, Schritte zur Reproduktion, Einschätzung der Auswirkung, relevante Logs/Screenshots/Proof-of-Concept und die betroffene Version bzw. den Commit-Hash.

### Reaktionszeit

Wir versuchen, gültige Meldungen innerhalb von 5 Werktagen zu bestätigen und so schnell wie möglich an einer Lösung zu arbeiten. Ggf. fragen wir während der Untersuchung nach weiteren Informationen.

### Verantwortungsvolle Offenlegung

Bitte gib den Maintainern Zeit zur Untersuchung und Behebung, bevor du etwas öffentlich machst, und nutze die Lücke nur so weit aus wie nötig, um sie zu verifizieren.

### Sensible Informationen

Teile niemals Bot-Tokens, API-Keys, Webhook-Secrets, OAuth-Zugangsdaten, Datenbank-Zugangsdaten oder private Umgebungsvariablen. Halte Secrets in lokalen Umgebungsdateien und committe sie nie ins Repository.

## 🇬🇧 English

### Supported versions

| Version | Supported |
| ------- | --------- |
| Latest `main` branch | ✅ Yes |
| Older releases | ❌ Not guaranteed |

### Reporting a vulnerability

We take security seriously. If you discover a security issue, please do **not** open a public issue or discuss it publicly.

Instead, report it privately, for example:

- Open a private GitHub security advisory (preferred if enabled)
- Contact the maintainers privately through GitHub
- Use the repository's private reporting mechanism if available

Please include: a description of the vulnerability, steps to reproduce, an impact assessment, any relevant logs/screenshots/proof of concept, and the affected version or commit hash.

### Response expectations

We aim to acknowledge valid reports within 5 business days and work toward a fix as quickly as possible. We may ask for additional information during the investigation.

### Responsible disclosure

Please give maintainers time to investigate and fix the issue before public disclosure, and only exploit the vulnerability as far as necessary to verify it.

### Sensitive information

Never share bot tokens, API keys, webhook secrets, OAuth credentials, database credentials, or private environment variables. Keep secrets in local environment files and never commit them to the repository.
